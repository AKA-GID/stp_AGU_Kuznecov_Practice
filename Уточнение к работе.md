# Уточнение к работе

## Наследование и интерфейс базового класса

```cpp
class Ebook : public Book {
public:
    Ebook(std::string title, std::string author, int year, int pages,
          std::string url);
private:
    std::string url_;
};
```

`Ebook : public Book` означает открытое наследование: объект электронной книги содержит базовую часть `Book`, а публичные методы родителя доступны через `Ebook`. Конструктор вызывает родительский конструктор в списке инициализации: `: Book(title, author, year, pages), url_(url)`. Так задаются поля базового объекта, а затем собственное поле URL.

Приватные поля `title_` и `author_` доступны только коду `Book`. Наследник читает их через публичные `title()` и `author()` и меняет через проверяющий `updateTitle()`. Прямое присваивание полю обходило бы инвариант базового класса.

## Сигнатуры методов и полиморфизм

`std::string url() const` возвращает строку URL, а `void download() const` выполняет действие и не возвращает значение. `const` после списка параметров обещает, что метод не меняет поля объекта.

```cpp
virtual std::string description() const;
std::string description() const override;
```

`virtual` в базовом классе разрешает динамическую диспетчеризацию. `override` в наследнике просит компилятор проверить, что сигнатура действительно переопределяет виртуальный метод. Вызов `book.description()` через `const Book&` тогда выбирает реализацию фактического типа `Ebook`.

```cpp
return Book::description() + " [URL: " + url_ + "]";
```

Квалифицированный вызов `Book::description()` переиспользует базовую реализацию и добавляет URL. Если вернуть только URL, клиент, ожидающий название, автора и год от любого `Book`, получит неполный результат — это нарушит постусловие базового интерфейса.

## Принцип подстановки Лисков

Клиент, работающий с `Book&`, должен корректно работать и с `Ebook`. Потомок сохраняет инварианты родителя, не вводит дополнительных ограничений и сохраняет обещанный результат.

- `clearTitle()` с прямым доступом к `title_` невозможен, пока поле `private`; перевод в `protected` разрешит обход проверки, но может оставить объект в недопустимом состоянии.
- Запрет в `Ebook::updateTitle()` на короткие названия усиливает предусловие. Безопасный вариант делегирует базовой проверке: `Book::updateTitle(std::move(new_title));`.
- `Book& base = ebook;` связывает ссылку на базовый интерфейс с объектом-потомком. Виртуальные методы сохраняют поведение фактического типа.

## Исключения и проверки

`std::invalid_argument` сообщает, что входное значение некорректно. `try` окружает потенциально ошибочный вызов; `catch (const std::invalid_argument& error)` ловит только этот вид исключения. Тесты проверяют виртуальные вызовы через базовую ссылку, полный текст описания, URL и то, что неудачное обновление не меняет состояние.
